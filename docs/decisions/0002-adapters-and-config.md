# ۰۰۰۲ — Adapterهای قابل تعویض، مقادیر دمو و کلیدهای تنظیمات اضافه‌شده

- وضعیت: پذیرفته‌شده (۲۰۲۶-۱۱-۰۴) — مالک: ثنا
- زمینه: سند (بخش ۰ و ۱۳) صریحاً می‌گوید هیچ قراردادی نمی‌تواند نام تجاری درگاه پیامک، سرویس نقشه،
  قواعد رسمی صلاحیت اهدا یا کلید API را از پیش تعیین کند. در محیط مسابقه هم نباید رازی در ریپو بنشیند.
- تصمیم:
  1. **SMS**: `app/services/sms_service.py` یک `SmsProvider` Protocol و پیاده‌سازی `MockSmsProvider` دارد.
     `SMS_PROVIDER` (مقادیر: `mock`) adapter را انتخاب می‌کند. در mock، پیام در حافظه ثبت می‌شود و
     شماره با `mask_phone` ماسک می‌گردد؛ تست‌ها از همین رکورد استفاده می‌کنند.
  2. **Maps**: `app/services/maps_service.py` با `MockMapsProvider` (هاورسین × سرعت ۳۰ کیلومتر/ساعت × ضریب ۱٫۲۵).
     اگر provider خطا دهد، `estimate_route()` به تخمین فاصله fallback می‌کند و `source` را `fallback` ثبت می‌کند
     تا در `/candidates` قابل توضیح باشد (بخش ۱۱.۴).
  3. **صلاحیت**: `DemoDeclaredTypePolicy` فقط «تطابق نوع اعلامی» را بررسی می‌کند و با برچسب
     `COMPATIBILITY_POLICY=demo` کار می‌کند. هیچ حدس بالینی، سازگاری گروه/فرآورده یا فاصله زمانی بین اهدا
     در کد تیم ساخته نمی‌شود (بخش ۱.۲ سند).
  4. **OTP store**: Redis اگر `REDIS_URL` پاسخ دهد، و در غیر این صورت `InMemoryChallengeStore`
     (برای تست و اجرای سریع محلی). کلیدهای rate-limit شامل HMAC شماره/IP هستند تا داده خام کلید نشود.
  5. **Celery broker**: اگر Redis در دسترس نباشد، endpoint فراخوان به‌صورت inline اجرا می‌کند تا دمو نشکند
     (`_enqueue_batch`)؛ زمان‌بندی مراحل از وضعیت دیتابیس بازیابی می‌شود (تصمیم ۰۰۰۳).
- کلیدهای تنظیمات اضافه‌شده نسبت به بخش ۱۳ سند (مقادیر MVP، قابل تغییر بدون مهاجرت):

| کلید | پیش‌فرض | کاربرد |
| --- | --- | --- |
| `OTP_RATE_LIMIT_WINDOW_SECONDS` | 3600 | پنجره سقف ارسال کد |
| `OTP_MAX_REQUESTS_PER_PHONE` | 5 | سقف هر شماره در پنجره |
| `OTP_MAX_REQUESTS_PER_IP` | 15 | سقف هر IP در پنجره |
| `COMPATIBILITY_POLICY` | `demo` | انتخاب سیاست تطابق؛ فقط `demo` مقدار واقعی دارد |
| `PUBLIC_APP_BASE_URL` | `http://localhost:5500` | پایه لینک امن پاسخ در پیامک و origin مجاز CORS |
| `DISPATCH_RESPONSE_WINDOW_MINUTES` | 15 | فاصله بین مراحل فراخوان |
| `SMS_DEV_OUTBOX_FILE` | خالی (`backend/.dev-outbox.log` در حالت توسعه) | صندوق پیام دمو: متن کامل پیامک (کد OTP و لینک پاسخ) را در یک فایل قابل‌خواندن می‌نویسد تا تیم بدون لاگ‌کردن راز، کد را ببیند؛ در production مقدارش باید خالی بماند و ویدیشن Settings آن را رد می‌کند |

- پیامد: برای اتصال درگاه واقعی فقط یک کلاس جدید + `SMS_PROVIDER=<name>` و راز در `.env` لازم است؛
  هیچ endpoint یا تستی تغییر نمی‌کند. تا روز دمو، هیچ مقدار واقعی کلید/رمز در ریپو (و در این فایل) مجاز نیست.
